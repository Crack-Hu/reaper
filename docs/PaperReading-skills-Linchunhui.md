# PaperReading-skills (Linchunhui) 深度分析

> 仓库: https://github.com/Linchunhui/PaperReading-skills  
> 版本: v7.0.0

## 1. 项目概述

**单一 Claude Code skill**（非 suite），功能极度聚焦：把一篇论文拆解成结构化的**单文件 HTML 阅读笔记**。让"不懂这个领域的聪明人"读完能复述四件事：问题、解法、核心发现、能带走的洞见。

## 2. 核心哲学

**"读论文不是做学术，是猎取思想"**

八大设计原则：
1. **外行优先于凝练**：正文该多长就多长，节奏由"让人懂"决定
2. **一个锚点撑全文**：Motivation 里立一个具象场景为锚点
3. **推理外显**：模拟"想明白的过程"而非"想明白的结果"
4. **变形替代定义**：概念解释把 A 变形成 B
5. **落点在能用**："你可以___"而非"值得思考___"
6. **公式必翻译**：每条 LaTeX 后加中文说明
7. **图片必核对**：边界完整、清晰、≤300KB
8. **6个月后看得懂**

## 3. 技术实现路径（重点）

### 第一层：内容获取（3种输入）

```
arxiv URL → WebFetch 拿abstract和正文 + PDF URL
本地 PDF  → Read 直接读取
论文名称  → WebSearch 找链接 → 走URL流程
```

配图策略：优先 arxiv HTML 版独立 PNG/SVG，兜底 `pdftoppm -png -r 200` 截图 → PIL 压缩 ≤300KB。

### 第二层：10节固定模板

| 节 | 核心规则 |
|---|---|
| 摘要 | 200-300字全景，覆盖四要素 |
| 一、Motivation | 三段大白话，立锚点贯穿全文 |
| 二、现存问题 | 3-5个前作问题，问题→后果一句 |
| 三、相关工作翻译 | 3-5个先驱方法，大白话重写 |
| 四、方法详解 | 每个子模块讲清"做什么/怎么做/为什么" |
| 五、实验结果 | 主结果+消融+SVG可视化 |
| 六、总结 | 最核心贡献+打开什么+留下什么 |
| 七、Insight | 按需出现，论文真正的新结晶 |
| 八、启发 | 三个视角：迁移/混搭/反转。落点"能动手的小动作" |
| 九、关键引用 | 3-5处原文+中文翻译 |
| 十、Q&A | 5-10道可折叠问题 |

### 第三层：写作规则引擎

**12条红线**（每条必须过）：口语检验、零术语裸奔、短词优先、一句一事、具体、开头给理由、不填充、信任读者、诚实、公式必翻译、6个月后看得懂、外行优先。

**4条写作原则**：锚点撑全文、推理外显、变形替代定义、落点能用。

### 第四层：工具箱

- **SVG 可视化**：7种场景（消融/主结果/方法流程/训练曲线/分布对比/架构图/因果链），每个数字必须能定位到论文 Table/Figure
- **KaTeX 渲染**：CDN 引入，公式有严格书写规范
- **配图管理**：三条同时满足（边界完整+清晰+≤300KB）

### 第五层：HTML 生成

调用 `frontend-design` skill 生成单文件 HTML，传入：全部正文 + 配图 base64 + 视觉风格规范。结构固定：`<header>` + `<main>`（10个section） + `<aside id="toc">`

### 第六层：15项质量验收

包括：h1朴素、摘要先行、锚点贯穿、Motivation落地、配图齐、SVG数据准确、实验有SVG、Insight真才写、启发能动手、Q&A 5-10道、公式都翻译渲染、HTML可读不臃肿。

## 4. 亮点

1. **极致的 prompt engineering**：600行 SKILL.md 驱动 Claude 产出高质量结构化笔记
2. **"外行检验"作为金标准**：所有规则汇到一个检验
3. **Insight 锚点机制**：AI 读完后"自己看到的那个东西"
4. **SVG 数据准确性**：定位到具体 Table/Figure，逐项核对
5. **单文件 HTML**：自包含、双击即用
6. **v7.0.0**：迭代了7个大版本的精炼

## 5. 对我们的启发

| 维度 | 启发 |
|------|------|
| 外行检验 | 作为笔记质量核心标准 |
| 锚点机制 | 全文围绕一个具象场景展开 |
| 宁缺毋滥 | Insight 按需出现、不硬挤 |
| SVG 准确 | "定位到单元格+逐项核对"防止幻觉 |
| 单文件 HTML | 自包含是巨大 UX 优势 |
| 红线+原则分层 | "必须过"和"应该做"清晰分离 |
