# PaperForge (FeijiangHan) 深度分析

> 仓库: https://github.com/FeijiangHan/PaperForge

## 1. 项目概述

**纯 Prompt/Skill 定义仓库**。整个仓库只有4个文件：`SKILL_CHN.md`、`SKILL_EN.md`、`System_Prompt.txt`、`README.md`。零依赖、零脚本。所有工作由 LLM 自身推理完成。

## 2. 核心思路

**"用结构化对话约束替代代码约束"**。核心理念：将论文阅读变成一套可复现的 12 节分析流程。

### 12 节分析流程

```
§1 研究问题与重要性
§2 前人工作与不足
§3 重建作者的思考路径（关键创新！）
§4 核心 Intuition
§5 具体方法与完整 Pipeline
§6 核心数学推导（可选）
§7 实验设计与结论
§8 Take-aways（5句/3句/1句三档）
§9 最脆弱的假设
§10 最小复现实验
§11 最强反例设计
§12 Follow-up Research Idea
```

## 3. 关键机制

### 四类信息源分类（系统抗幻觉机制）

1. **论文原文明确声称**：作者显式claim
2. **相关文献已有结论**：文献记录结果
3. **基于证据的合理推断**：逻辑推出
4. **仍然不确定的猜测**：无直接证据

> "不要把推断写成事实，不要把猜测写成推断。"

### §3 逆向推理

**不能使用论文自己的贡献作为前提**。只用论文发表前存在的背景、失败模式、经验观察、理论线索。迫使 Agent 做真正的逆向推理。

## 4. 亮点

- 极简主义极致：4个文件零依赖
- §3 逆向推理是独一无二的设计
- 四类信息源分类系统对抗幻觉
- 反例设计："最强反例"而非简单问"有什么局限"
- "非增量式" follow-up 要求

## 5. 对我们的启发

- Skill 可以极简——足够好的 Prompt 本身就是产品
- 信息来源分级是抗幻觉有效手段
- 逆向推理环节值得引入
- 12节结构可作为报告模板参考
- 风格约束（如"先写claim再写evidence"）比抽象要求更有效
